# Contributing

Welcome. We are recruiting a small international founding group and welcome constructive contributions from anyone.

## Begin with discussion

1. Read the README, vision, provisional governance, and feasibility questions.
2. Introduce yourself in GitHub Discussions (background, expertise, interests, approximate availability). Do **not** post sensitive personal information.
3. Comment on a relevant discussion or propose a narrowly scoped research task.
4. Before submitting code, open an Issue describing the problem, alternatives, security implications, and acceptance criteria.

## Priority contributions

- Evidence-based comparisons of distributed versus centralized inference
- Model and runtime evaluation on heterogeneous hardware
- Secure workload orchestration and data protection
- Agent-assisted operations with permission boundaries and audit logs
- Cost modeling, fair compensation, governance, and sustainability

## Working principles

Be respectful, technically rigorous, internationally inclusive, and candid about uncertainty. Disclose material conflicts of interest. Avoid hype, unverified cost claims, or promises of returns. Do not upload private datasets, credentials, proprietary model weights, or sensitive personal information.

## Volunteer status and rights

Initial participation is voluntary and does not create employment, equity, ownership, compensation, or investment rights. No contributor reward scheme has yet been approved. Licensing and intellectual-property terms must be finalized before accepting substantive code contributions; until then, focus on discussions, documentation, and research proposals. Do not submit code that cannot legally be shared.

## Proposed workflow

Discussions → scoped Issue → review → implementation (after licensing and architecture decisions) → testing → documented decision.

See [GOVERNANCE.md](GOVERNANCE.md) for provisional procedures.
